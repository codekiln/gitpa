# Publish Ghost in the Patch

The website is generated by [Logseq Gardener](https://github.com/codekiln/logseq-gardener). The checked-in `gitp-garden` and podcast RSS remain the publication sources.

Install the tools with `mise install` and the parser dependency with `npm ci`. `mise install` provides `lsg` at the latest release, shared with the global mise install. Then generate a fresh output directory:

```sh
mkdir -p /private/tmp/gitpa-preview
python3 scripts/build_site.py --renderer "$(mise which lsg)" --output /private/tmp/gitpa-preview/gitpa
python3 -m http.server --directory /private/tmp/gitpa-preview 8765
```

Open [the preview homepage](http://localhost:8765/gitpa/). The home page retains the introduction, subscription link, fly artwork, and Recent Ceremonies list. `lsg` runs the authored Logseq query, result transform and Hiccup view at build time, as Logseq's published site does. `mise run site:query:check` runs the same query with the Logseq file parser; the homepage lists the same episodes in the same order.

The light Nord stylesheet applies to the homepage, episode pages, and reference pages. Logseq Gardener renders page and block transclusions and recording controls. Episode preparation continues to select public notes and derive asset visibility from published episodes. The build includes explicitly public pages, copies the existing RSS, and adds the GitHub Pages `.nojekyll` marker. Each published page has a readable namespace URL such as `GitP/A/Session/26/10/20-Tue/`. RSS items link directly to these pages. Existing hashed page files and `#/page/...` links remain usable; generated navigation goes to namespace URLs. Recording controls retain native keyboard and seeking support. The original podcast artwork path is copied alongside the renderer’s assets so subscribed podcast clients keep a working image URL. Publication validates every RSS episode link against an emitted page.

Authored `collapsed:: true` outlines start closed using Gardener’s native disclosure controls. Click the label or focus it and press Enter to expand the children. Links to a descendant open its enclosing branches before scrolling, including during internal navigation. Unrelated branches keep their state.

Readers can also fold other blocks with children using the arrow beside the bullet. The controls support keyboard and touch, including nested headings. Page properties start open; opening or closing Properties sets a site-wide preference that follows internal navigation and reloads. After thirty days without a visit, properties return to the configured default. When browser storage is unavailable, the configured default applies.

Every page ends with an expanded, collapsible Hierarchy section. Its flat list shows the current full namespace path followed by all published descendants, including deeper levels. Each available segment links to its cumulative namespace: in `A/B/C/E/F`, `C` links to `A/B/C` and `F` links to `A/B/C/E/F`. Leaf pages retain their current path so readers can navigate upward. Gardener generates navigation pages for missing intermediate namespaces, and packaging gives those pages readable URLs. Private and unpublished stored pages remain withheld.

Run `python3 -m unittest discover -s tests`, `node --test tests/*.test.js`, `mise run site:query:check`, and `mise run rss:check` before publication. Review the generated homepage, chapter seeking in an episode, and an instrument manual with transclusions. PR builds upload the complete `gitpa-website` preview; merging publishes the same output to GitHub Pages.

### Upgrade Logseq Gardener

The Publish workflow ignores the `lsg` entry in `mise.toml` (`MISE_DISABLE_TOOLS` on the mise step) and instead downloads a released Linux build of `lsg` and checks it against a pinned SHA-256 hash before use. A changed or replaced release file fails the build. To move to a newer release:

1. In `.github/workflows/gh-pages.yml`, set `GARDENER_VERSION` to the new release tag, such as `v0.0.2`.
2. Set `GARDENER_SHA256` to the hash in that release's `logseq-gardener-x86_64-unknown-linux-gnu.tar.xz.sha256` file. `gh release download <tag> --repo codekiln/logseq-gardener --pattern '*x86_64-unknown-linux-gnu.tar.xz.sha256' --output -` prints it.
3. Open a pull request. The build log shows the `lsg --version` output, and the uploaded `gitpa-website` preview shows the result of the new renderer.

`scripts/build_site.py` finds rendered pages through Gardener's `lsg-site.json` route list, then adds the Copy feed URL button beside the homepage's feed link. If a new release changes that output, the publish step stops with a message that names the missing page or link.

## Search

Search uses Gardener's shared static index and dialog. Open it from the header search button or with Cmd/Ctrl+K. Results include published page titles, unique aliases and original note text. Page results open readable namespace URLs; note results open their source block and reveal its enclosing collapsed outlines. Internal result navigation keeps the current recording and appearance setting.

Generate a search-enabled preview with `python3 scripts/build_site.py --renderer "$(mise which lsg)" --search --output /private/tmp/gitpa-search-preview/gitpa`. Search data loads on first opening, and subsequent opens reuse the current publication's prepared index. Loading errors offer retry and reload; search never reloads the page automatically.

Only selected public source content enters the index. Homepage query rows, copied backlink/transclusion content, hidden properties and unresolved reference identities are excluded. This first index version searches original note text rather than page-property values or generated namespace titles. The authored homepage introduction remains searchable. The legacy route map loads only when a legacy page fragment is opened.

## Previous and Next

A page with `prev::` or `next::` page properties shows its previous page at the left of the header with a left arrow and its next page at the right with a right arrow, each with the page title. Below 640px the header shows only the arrows, and the title remains each link's accessible name. The links come from the rendered `prev` and `next` property rows, or from Gardener's `nav.page-sequence` links, and change with in-site navigation. The property rows stay on the page.

The links come from Gardener's first-party `sequence-header` plugin, turned on with `:lsg/plugins` in `gitp-garden/logseq/config.edn`. Gardener's plugin host loads it only on pages with `prev::` or `next::`.

## Illuminated initials

Published episodes decorate the opening letter of Ceremonial Annotations and the first chapter title, when those sections are present. The browser draws the garden and chooses its details from the page title, so each episode keeps its own design across visits. The original text remains available without JavaScript. `site/illuminated-initials.js` is a Gardener site plugin with the manifest `site/illuminated-initials.lsg-plugin.json`; `site/illuminated-initials.css` supplies its layout. It treats a page as an episode when Gardener's page metadata has an entry for the `podcast-episode` plugin.

## Episode chapters

Gardener's first-party `podcast-episode` plugin plays each published episode. `gitp-garden/logseq/config.edn` turns it on with `:lsg/plugins [:podcast-episode]`, and [lsg/Ref/First-Party Plugins](https://github.com/codekiln/logseq-gardener/blob/main/logseq-gardener-docs/pages/lsg___Ref___First-Party%20Plugins.md) describes what it does. The episode's native audio controls stay in a fixed footer while the reader follows links within the site. The timestamp at the start of a chapter heading (H3 to H6), of a bullet under `## Chapters`, or of a dialogue line seeks and plays that recording; a modified click opens the recording itself at that time. The footer names the episode and shows the chapter playing now with its enclosing chapters, each linked to its notes. Browsing another episode offers a Play button and keeps the current recording playing until the listener presses it. Playback starts only after the listener selects a timestamp or the recording controls.

Keep the episode text in logseq-encode-garden with one direct full-recording embed and plain timestamp chapter headings:

```markdown
- # Episode title
	- ![Full recording](https://example.com/episode.mp3)
	- ## Chapters
		- ### 14:42 Adapters and input modes
			- Chapter notes.
```

The example uses tabs for outline indentation. Plain timestamps at the start of H3 through H6 headings, and of bullets under `## Chapters`, remain readable in Logseq and become seek controls in the browser. The published-site `{{audio-timestamp 14:42}}` extension is also supported: publication writes it as its readable time, such as `14:42`. Its timestamps accept integer seconds, `M:SS`, or `H:MM:SS`, with two-digit minutes and seconds after a colon. Macros shown in fenced or inline code remain literal.

Re-sync the exact episode page with the imported `logseq:entity:proxy:page:sync` task, passing the source garden, `--destination gitp-garden`, `--page GitP/A/Session/26/10/20-Tue`, and `--apply`. Sync copies source text and its `public::` choice while keeping the proxy's `tags::`, `podcast-guid::`, and `podcast-published-at::`. Repeating the same sync keeps the canonical chapter headings and release identity unchanged. Run the RSS and publication checks after syncing.

Chapter headings need only the full MP3 and their timestamps. Separate chapter MP3s and waveform images are unnecessary. Publication removes the existing derived chapter media from the temporary episode view while retaining chapter notes and unrelated artwork; checked-in garden pages stay unchanged. Without JavaScript, the recording keeps its native controls in the page and chapter timestamps stay text.

`scripts/audio_chapters.py` checks for the one full recording, removes derived chapter media and writes `audio-timestamp` macros as times, before `lsg` renders the graph. Gardener's plugin host owns navigation between pages, so the same audio element keeps playing; refreshing or leaving the site stops playback. RSS recording URLs and GUIDs remain unchanged.

The homepage's Copy feed URL button is `site/copy-feed.js`, which `scripts/build_site.py` adds to the homepage beside the button.

## Ableton Set track view

A page typed `logseq-entity:: [[Logseq/Entity/Ableton/Set]]`, such as [GitP/A/Session/26/11/06-Fri/Set](https://codekiln.github.io/gitpa/GitP/A/Session/26/11/06-Fri/Set/), opens with a track view: one column per track, side by side as in Live's Session View, with a group's tracks inside the group's column. Each column shows the track's type, input and output routing, MIDI channel, monitor and arm state and devices in chain order, and its name links to the track's page. A routing to another track of the Set links to that track's page. The row of tracks scrolls sideways. The page's outline, with the Set's notes and the embedded track pages, stays below.

The view comes from Gardener's first-party `ableton-set` plugin, turned on with `:lsg/plugins` in `gitp-garden/logseq/config.edn`. The logseq-encode-garden site turns on the same plugin at the same Gardener version, and Gitpa adds no code of its own, so both sites draw the same view from the same pages. At build time the plugin reads the settings written under each track page's heading, such as `type::`, `audio-from::`, `monitor::` and `devices::`, and Gardener's plugin host loads the view only on Set pages. [lsg/Ref/First-Party Plugins](https://github.com/codekiln/logseq-gardener/blob/main/logseq-gardener-docs/pages/lsg___Ref___First-Party%20Plugins.md) lists what the plugin reads.

To publish a session's Set, mirror its Set page with the pages it embeds: `mise run logseq:entity:proxy:page:sync --source /path/to/logseq-encode-garden --destination gitp-garden --page 'GitP/A/Session/26/11/06-Fri/Set' --follow-embeds --apply`. The garden owns `public::` on Set, group and track pages, so the sync brings `public:: true` with each page and Gitpa sets nothing by hand. A group or track page the garden has not marked public has no column, and the build reports the embed as unavailable. In the garden, `mise run ableton:set:import --public` writes the pages from a `.als` file and marks them; [Logseq/Entity/Ableton/Set](https://github.com/codekiln/logseq-encode-garden/blob/main/pages/Logseq___Entity___Ableton___Set.md) describes it.

## Deployment

The Publish workflow saves a website preview for every pull request. Runs on main publish that artifact to `gh-pages`, request a Pages build, and wait until the public `publication.json` matches the source revision and workflow run. Production jobs run serially and skip a revision when main has advanced before deployment begins. The build job has read access; the production job has repository content and Pages write access.

If generation succeeds but deployment fails, inspect the deploy job before rerunning Publish on main. A Pages build failure or a live revision that stays outdated fails the job. The existing site remains available while Pages builds. `publication.json` records only the public source commit and run ID.

GitHub documents that [workflow pushes using GITHUB_TOKEN do not trigger Pages builds](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site); the workflow uses the [Pages build API](https://docs.github.com/en/rest/pages/pages#request-a-github-pages-build) explicitly.
