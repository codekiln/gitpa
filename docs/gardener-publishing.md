# Publish Ghost in the Patch

The website is generated by [Logseq Gardener](https://github.com/codekiln/logseq-gardener). The checked-in `gitp-garden` and podcast RSS remain the publication sources.

Install the pinned tools with `mise install` and the parser dependency with `npm ci`. Build `lsg` from the renderer revision pinned in the Pages workflow, then generate a fresh output directory:

```sh
mkdir -p /private/tmp/gitpa-preview
python3 scripts/build_site.py --renderer /absolute/path/to/lsg --output /private/tmp/gitpa-preview/gitpa
python3 -m http.server --directory /private/tmp/gitpa-preview 8765
```

Open [the preview homepage](http://localhost:8765/gitpa/). The home page retains the introduction, subscription link, fly artwork, and Recent Ceremonies list. The build evaluates the authored Logseq query, result transform, and Hiccup view through the same parser used by `site:query:check`; the prepared publication graph receives ordinary links in the evaluated order. The source query stays in the garden. An unsupported query view or a result linking to a missing or unpublished page stops publication.

The light Nord stylesheet applies to the homepage, episode pages, and reference pages. Logseq Gardener renders page and block transclusions and recording controls. Episode preparation continues to select public notes and derive asset visibility from published episodes. The build includes explicitly public pages, copies the existing RSS, and adds the GitHub Pages `.nojekyll` marker. Each published page has a readable namespace URL such as `GitP/A/Session/26/10/20-Tue/`. RSS items link directly to these pages. Existing hashed page files and `#/page/...` links remain usable; generated navigation goes to namespace URLs. Recording controls retain native keyboard and seeking support. The original podcast artwork path is copied alongside the renderer’s assets so subscribed podcast clients keep a working image URL. Publication validates every RSS episode link against an emitted page.

Authored `collapsed:: true` outlines start closed using Gardener’s native disclosure controls. Click the label or focus it and press Enter to expand the children. Links to a descendant open its enclosing branches before scrolling, including during internal navigation. Unrelated branches keep their state.

Readers can also fold other blocks with children using the arrow beside the bullet. The controls support keyboard and touch, including nested headings. Page properties start open; opening or closing Properties sets a site-wide preference that follows internal navigation and reloads. After thirty days without a visit, properties return to the configured default. When browser storage is unavailable, the configured default applies.

Every page ends with an expanded, collapsible Hierarchy section. Its flat list shows the current full namespace path followed by all published descendants, including deeper levels. Each available segment links to its cumulative namespace: in `A/B/C/E/F`, `C` links to `A/B/C` and `F` links to `A/B/C/E/F`. Leaf pages retain their current path so readers can navigate upward. Gardener generates navigation pages for missing intermediate namespaces, and packaging gives those pages readable URLs. Private and unpublished stored pages remain withheld.

Run `python3 -m unittest discover -s tests`, `node --test tests/*.test.js`, `mise run site:query:check`, and `mise run rss:check` before publication. Review the generated homepage, chapter seeking in an episode, and an instrument manual with transclusions. PR builds upload the complete `gitpa-website` preview; merging publishes the same output to GitHub Pages.

## Search

Search uses Gardener's shared static index and dialog. Open it from the header search button or with Cmd/Ctrl+K. Results include published page titles, unique aliases and original note text. Page results open readable namespace URLs; note results open their source block and reveal its enclosing collapsed outlines. Internal result navigation keeps the current recording and appearance setting.

Generate a search-enabled preview with `python3 scripts/build_site.py --renderer /absolute/path/to/lsg --search --output /private/tmp/gitpa-search-preview/gitpa`. Search data loads on first opening, and subsequent opens reuse the current publication's prepared index. Loading errors offer retry and reload; search never reloads the page automatically.

Only selected public source content enters the index. Evaluated homepage query rows, copied backlink/transclusion content, hidden properties and unresolved reference identities are excluded. This first index version searches original note text rather than page-property values or generated namespace titles. The authored homepage introduction remains searchable. The legacy route map loads only when a legacy page fragment is opened.

## Episode chapters

Each published episode uses one full recording. Its native audio controls stay in a fixed footer while the reader scrolls or follows links within the site. Selecting a chapter timestamp seeks and plays that recording. The footer follows the chapter at the current playback time; selecting the chapter name opens its notes. “Return to start” opens the chapter or episode position where the listener started playback. Playback starts only after the listener clicks a chapter or the recording controls.

Keep the episode text in logseq-encode-garden with one direct full-recording embed and plain timestamp chapter headings:

```markdown
- # Episode title
	- ![Full recording](https://example.com/episode.mp3)
	- ## Chapters
		- ### 14:42 Adapters and input modes
			- Chapter notes.
```

The example uses tabs for outline indentation. Plain timestamps remain readable in Logseq and become chapter controls during publication, including time ranges. The published-site `{{audio-timestamp 14:42}}` extension is also supported; its timestamps accept integer seconds, `M:SS`, or `H:MM:SS`, with two-digit minutes and seconds after a colon. Macros shown in fenced or inline code remain literal.

Re-sync the exact episode page with the imported `logseq:entity:proxy:page:sync` task, passing the source garden, `--destination gitp-garden`, `--page GitP/A/Session/26/10/20-Tue`, and `--apply`. Sync copies source text and its `public::` choice while keeping the proxy's `tags::`, `podcast-guid::`, and `podcast-published-at::`. Repeating the same sync keeps the canonical chapter headings and release identity unchanged. Run the RSS and publication checks after syncing.

Chapter headings need only the full MP3 and their timestamps. Separate chapter MP3s and waveform images are unnecessary. Publication removes the existing derived chapter media from the temporary episode view while retaining chapter notes and unrelated artwork; checked-in garden pages stay unchanged. Without JavaScript, the recording retains native controls and chapter links open the full recording at a media time fragment.

`scripts/audio_chapters.py` handles timestamp parsing and outline preparation. `site/player.js` controls the existing audio element and chapter timeline, `site/navigation.js` handles internal navigation and browser history, and `site/player.css` styles the footer. Player and navigation assets load on every published page, including readable and compatibility URLs. Internal navigation replaces the page content while keeping the same audio element alive. Browsing another episode offers a “Play this episode” button and keeps the current recording playing until the listener chooses to switch. External links, downloads, refreshes and leaving the site use normal browser navigation; refreshing or leaving the site stops playback. Without JavaScript, pages and native recording controls still work. RSS recording URLs and GUIDs remain unchanged.

## Deployment

The Publish workflow saves a website preview for every pull request. Runs on main publish that artifact to `gh-pages`, request a Pages build, and wait until the public `publication.json` matches the source revision and workflow run. Production jobs run serially and skip a revision when main has advanced before deployment begins. The build job has read access; the production job has repository content and Pages write access.

If generation succeeds but deployment fails, inspect the deploy job before rerunning Publish on main. A Pages build failure or a live revision that stays outdated fails the job. The existing site remains available while Pages builds. `publication.json` records only the public source commit and run ID.

GitHub documents that [workflow pushes using GITHUB_TOKEN do not trigger Pages builds](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site); the workflow uses the [Pages build API](https://docs.github.com/en/rest/pages/pages#request-a-github-pages-build) explicitly.
