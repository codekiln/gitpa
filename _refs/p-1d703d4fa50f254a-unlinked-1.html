Logseq/Entity/Definition
  • Logseq/Entity/Person, Logseq/Entity/Software/Project, Logseq/Entity/Book, and the other pages under the Logseq/Entity/ namespace.
  • A page under the Logseq/Entity/ namespace whose job is to define one entity type: what counts as an instance, what does not, how to name and deduplicate it, and what shape its instance pages take.
Logseq/Entity/Discussion
  • The subject can be any page: an entity definition such as Logseq/Entity/Music/Scale, a principle such as My/Principle/Simplify/Prefer Standards and Defaults, or a preference such as My/Pref/Dev/mise/Tasks. The subject page may exist only as a logical page, as Logseq/Entity/Hierarchy does.
  • H1 — the subject page's H1 followed by Discussion: - # Music Scale Discussion for Logseq/Entity/Music/Scale, whose H1 is Music Scale. When the subject has no page file, the H1 names the subject in Title Case without the Logseq/ prefix, as - # Entity Hierarchy Discussion does for Logseq/Entity/Hierarchy. Logseq/Entity/Definition/Discussion keeps the H1 codekiln wrote for it.
Logseq/Entity/Frontmatter/Definition
  • Ownership follows the namespace: Logseq/Entity/<Type>/Frontmatter/<key> belongs to Logseq/Entity/<Type>. A separate ownership property or body section would repeat that relationship.
  • A Frontmatter Definition lives under its owning type at Logseq/Entity/<Type>/Frontmatter/<key>, where <key> is the literal frontmatter key it defines, in kebab-case to match the :: property (for example dotfiles-dep-stage).
  • When the property draws from a closed set, enumerate the permitted values as child pages Logseq/Entity/<Type>/Frontmatter/<key>/<Value>. An instance references a value page, which gives autocomplete and turns each value page's linked references into the list of instances currently holding that value.
Logseq/Entity/Preset/Synth/Microfreak/Frontmatter/preset-synth-microfreak-category
  • Page-link autocomplete under Logseq/Entity/Preset/Synth/Microfreak/Frontmatter/preset-synth-microfreak-category/ lists the category pages. Logseq Properties explains property names, value autocomplete and page references.
Logseq/Entity/Software/Project
  • To mark a page as a software project instance, add logseq-entity:: pointing at this type page (the namespace uses nested segments: Logseq/Entity/Software/Project). The type page then gets backlinks to all software project pages.
Microfreak/Log/26/09/28 Mon Preset Management
  • in logseq, one can click on a frontmatter item and be taken to a page. For example, preset-on-device is literally the page preset-on-device. I want to develop or work towards a convention that when frontmatter is defined in a logseq entity, then the frontmatter defined and requested by that entity should be related to the entity, for provenance and data definition reasons, and the page for the custom frontmatter attribute must be filled in with its definition - and that definition should be of type Logseq/Entity/Frontmatter/Definition. There's a design tension here. If we click on a certain property, say, preset-on-device, we are taken to a page that is not a subnamespace of Logseq/Entity/Preset/Synth the way that definition page describes. One way around this would be to create Logseq/Entity/Preset/Frontamtter/preset-on-device with an alias of preset-on-device, so that clicking on preset-on-device would take it to the appropriate location in the garden. I think we need to further stipulate that prefixes should have a certain type of namespacing. For example, in the entity system, Logseq/Entity/X/Y/Z/Frontmatter/Fruit should likely lead to frontmatter key x-y-z-fruit. We don't need to do this everywhere just yet, but in this synth preset space, I'd like to do this.
