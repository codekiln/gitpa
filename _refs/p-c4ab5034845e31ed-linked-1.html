Logseq/Entity/Book
Book
  • Standard Logseq/Frontmatter rules
    • Mark instances with logseq-entity:: [[Logseq/Entity/Book]] so this type page collects backlinks to every book entity.
    • When the author is clear, set created-by:: [[Person/Full Name]], [[Person/Full Name 2]] in frontmatter and ensure that person entity is in the garden.
    • The publication year is usually already carried in the page's own namespace segment (the YY in Person/<name>/Book/YY/<short title>), but that text is not a link. Optional: logseq-created-time-year:: linking to the matching Logseq/Entity/Time/Year instance makes it one.

Logseq/Entity/Frontmatter/Definition
Frontmatter Definition
  • In this garden, Frontmatter Definition pages model a custom frontmatter property that one entity type adds for its instances — the property's meaning, its permitted values, and how instances set it. Global, cross-type conventions stay on Logseq/Frontmatter; a Frontmatter Definition is scoped to a single entity type.
Frontmatter DefinitionWhat counts as an instance
  • Not an instance: a shared convention on Logseq/Frontmatter (those apply to every page, not one type); a Logseq/Entity/Definition page (that defines an entity type, not a property); an individual permitted value.

Logseq/Entity/Music/Recording
Music RecordingNaming and placement
  • Place a recording under its first credited Logseq/Entity/Identity/Music as <Identity>/Music/Recording/<Title> when Logseq/Frontmatter/created-by-identities is present. For a joint release, keep one page under the first credited identity and list all credited identities. Without a separate identity, use Person/<Artist>/Music/Recording/<Title>. Existing group namespaces remain valid until deliberately renamed.
Music RecordingRelationships
  • Use Logseq/Frontmatter/created-by-identities for published artist credits; created-by:: and performer:: retain verified personal credits rather than being inferred from identity membership.
