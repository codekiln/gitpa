Logseq/Entity/UI/Area
UI AreaWhat counts
  • A single knob, button, pad or field is a Logseq/Entity/UI/Control, not an area.
UI AreaAtomic Design stages
  • A Logseq/Entity/UI/Control corresponds to an UX/Design/Atomic/L1 - Atom. A preset or a saved Live Set, which fills the interface with real values, corresponds to an UX/Design/Atomic/L5 - Page and is modeled by its own entity.
UI AreaIdentity and names
  • Inside a row, or on a side without rows, each item takes a two-digit number counting left to right: 01 Matrix, 02 Paraphonic Button. A numbered group of controls is an area, such as Microfreak/UI/Front/Row/01 Top/01 Matrix; a numbered single control is a Logseq/Entity/UI/Control.
UI AreaPage shape
  • A ## Controls section links each Logseq/Entity/UI/Control in the area, in panel or screen order. A ## Areas section links smaller areas when there are any. Link rather than embed; control pages are short and many.
Logseq/Entity/UI/Control
UI ControlIdentity and names
  • Place a control at <Item>/UI/<Area>/<Kind>/<Name>, under the Logseq/Entity/UI/Area that holds it.
UI ControlIdentity and names
  • A control that selects among named modes has one page per mode beneath it, and a parameter that only exists in one mode has its page beneath that mode: Logseq/Entity/UI/Control/Setting.
UI ControlPage shapeOptional blocks, in this order, when they apply:
  • Behavior — how the control changes its value, from Logseq/Entity/UI/Control/Kind.
Logseq/Entity/UI/Control/Kind
UI Control Kind
  • A proposal for describing how a Logseq/Entity/UI/Control changes its value, apart from the protocol that carries it. Not yet a preference.
Logseq/Entity/UI/Control/Setting
UI Control Setting
  • In this garden, UI Control Setting pages model one mode a Logseq/Entity/UI/Control selects, one parameter that exists only in such a mode, or one gesture that gives the control another function.
